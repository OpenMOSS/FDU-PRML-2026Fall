# 数据格式与状态检查

## 数据文件

测试标注为 `test_data/games_data_test.json`；两个参考生成器的标注为其输出目录下的 `data.json`，均为 JSON 数组。图片和状态路径相对于对应标注文件所在目录解析。

| 字段 | 含义 |
| --- | --- |
| `game_name` | 游戏名称 |
| `data_id`、`question_id` | 样本标识与题型编号 |
| `image` | 图片相对路径 |
| `state` | 完整游戏状态 JSON 的相对路径 |
| `question` | 原始问题文本，选择题包含选项文本 |
| `options` | 结构化选项；部分题目没有该字段或为 null |
| `answer` | 参考答案，可能是选项标签或自由形式答案 |
| `analysis` | 生成器提供的程序分析过程；不保证所有数据都有此字段 |
| `qa_type`、`qa_level` | 任务类型、任务难度 |
| `plot_level` | 棋盘难度 |
| `question_description` | 题型说明 |

不要统一假设答案是从0或1开始的选项编号；不同游戏/题型使用数字、字母或自由形式答案。统一评测器负责相应解释。图片、问题、选项、答案和state必须描述同一个样本。

## 状态

Sokoban 的 `grid` 用0–6编码空地、墙、箱子、目标、目标上的箱子、玩家、目标上的玩家，并保存玩家、箱子、目标等辅助字段。Maze 的 `maze` 编码空地0、墙1、玩家2、终点3，并保存尺寸、玩家与终点位置。具体格式见对应生成器及测试状态文件。

Snake 沿用的测试记录中虽有历史 `state` 路径，但没有提供相应状态文件；该字段不能作为可读取文件使用。测试推理不依赖state。

## 完整状态排重

```bash
python generators/state_guard.py my-data/sokoban/data.json
python generators/state_guard.py my-data/maze/data.json
```

两个参考生成器会在生成问题前排除测试状态，以上命令用于对最终数据再次检查。排重根据游戏名、棋盘尺寸和所有格子的完整状态进行，不依赖文件名、图片样式、问题或分析过程。仅完整状态相同时排除，不额外将旋转、镜像判为相同状态。训练与验证也应按游戏状态分开，避免同一棋盘不同问题跨集合。

该工具只支持 Sokoban/Maze 的既定状态格式；遇到其他游戏会明确报“不支持核验”，不会静默跳过后宣称检查通过。这不表示禁止所有其他训练游戏。自行扩展状态格式或构建新生成器时，应确保 Sokoban/Maze 的完整状态排重仍然有效。

检查发现重合、状态文件缺失或格式错误时返回非零退出码。输出中的 `overlap_rows` 是重合问答条数，不是去重后的棋盘数量。保留生成数据的状态文件，以便检查和复现。
